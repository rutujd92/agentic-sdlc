# Design

Extend the Core LinkValidator with an optional blockedDomains constructor parameter (normalized to a lower-case FrozenSet) and a suffix walk over the host labels, so a listed domain blocks itself and its subdomains but not look-alikes. Add ShortenerOptions.BlockedDomains (IReadOnlyList<string>, default empty) bound from configuration, and pass it when Program.cs constructs the singleton LinkValidator. LinkService and the endpoints already map InvalidUrl to 400 ProblemDetails, so no API code changes. The constructor parameter is optional, so existing callers and tests are unaffected.

## Impacted files
- src/UrlShortener.Core/Links/LinkValidator.cs
- src/UrlShortener.Api/ShortenerOptions.cs
- src/UrlShortener.Api/Program.cs
- tests/UrlShortener.Tests/Core/LinkValidatorDenylistTests.cs
- tests/UrlShortener.Tests/Api/BlockedDomainsTests.cs
- CHANGELOG.md

## API and schema changes
No new endpoints. POST /api/links returns 400 with detail 'URL points to a blocked domain.' for denylisted hosts. Config: Shortener:BlockedDomains (string array). Code: new LinkValidator(string ownHost, IEnumerable<string>? blockedDomains = null). API tests can set the denylist with WebApplicationFactory.WithWebHostBuilder(b => b.UseSetting("Shortener:BlockedDomains:0", ...)).

## Risks
- A static denylist goes stale; a reputation feed can be added behind the same validator later
- Existing links to newly listed domains still redirect (re-validation at redirect time is out of scope)

# Requirements

Users can create short links to known-malicious domains, which lends them our domain's credibility in phishing and malware campaigns.

## Acceptance criteria
- Shortener:BlockedDomains (array) configures the denylist; empty by default
- Creating a link whose host is a listed domain or any subdomain returns 400 ProblemDetails with detail 'URL points to a blocked domain.'
- Matching is case-insensitive and ignores a trailing dot; look-alikes (notevil.example) are not blocked
- Links to other domains behave exactly as before

## Assumptions
- The denylist is maintained by operators via configuration
- Existing links are not re-validated

## Open questions
- None

## Out of scope
- Link expiry
- Preview/interstitial page
- External reputation services
- Re-validating existing links at redirect time
