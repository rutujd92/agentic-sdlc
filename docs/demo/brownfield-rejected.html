# Design

Add a Click entity and IClickRepository (RecordAsync, RecentAsync) in Core; EfClickRepository and the clicks table mapping in Infrastructure (FK LinkId -> links.Id, cascade delete, index (LinkId, Id)); register it in DependencyInjection. In LinkEndpoints, the redirect records a click after the atomic counter increment (TimeProvider for the timestamp, headers truncated to Click.MaxReferrerLength / MaxUserAgentLength); stats returns RecentClicks from RecentAsync(link.Id, 10). Recent ordering uses the identity key (insertion order) because SQLite (used by the integration tests) cannot ORDER BY DateTimeOffset. The EF model changes, so a migration is required.

## API and schema changes
GET /api/links/{code}/stats adds `recentClicks: [{ occurredAt, referrer, userAgent }]` (additive, backwards compatible). Types: UrlShortener.Core.Links.Click { Id, LinkId, OccurredAt, Referrer, UserAgent, MaxReferrerLength=2048, MaxUserAgentLength=512 }, IClickRepository, UrlShortener.Infrastructure.Persistence.EfClickRepository(ShortenerDbContext), Api ClickResponse(OccurredAt, Referrer, UserAgent). New table clicks.

## Risks
- Write amplification: one insert per redirect (acceptable at current scale; batch or queue later)
- Table growth without retention policy (out of scope; tracked)
- Schema migration on a live table: additive only, no data rewrite

+using Microsoft.EntityFrameworkCore;
+using UrlShortener.Core.Links;
+
+namespace UrlShortener.Infrastructure.Persistence;
+
+public sealed class EfClickRepository(ShortenerDbContext context) : IClickRepository
+{
+    public async Task RecordAsync(Click click, CancellationToken cancellationToken)
+    {
+        context.Clicks.Add(click);
+        await context.SaveChangesAsync(cancellationToken);
+    }
+
+    // Ordered by the identity key (insertion order): SQLite cannot ORDER BY DateTimeOffset, and Id is monotonic.
+    public async Task<IReadOnlyList<Click>> RecentAsync(long linkId, int count, CancellationToken cancellationToken) =>
+        await context.Clicks.AsNoTracking()
+            .Where(c => c.LinkId == linkId)
+            .OrderByDescending(c => c.Id)
+            .Take(count)
+            .ToListAsync(cancellationToken);
+}

requirements e4a4d1a80bfe
# Requirements

The service only keeps a click counter, so we cannot see where traffic comes from or when.

## Acceptance criteria
- Each redirect stores a click with UTC timestamp, Referer header and User-Agent header
- Missing headers are stored as null; values are truncated to safe lengths (referrer 2048, user agent 512)
- GET /api/links/{code}/stats includes recentClicks: up to 10 most recent clicks, newest first
- The existing clickCount behaviour is unchanged (still atomic)
- Clicks are deleted when their link is deleted

## Assumptions
- Storing referrer and user agent is acceptable (no personal identifiers such as IP addresses are stored)
- 10 recent clicks are enough for the stats view

## Open questions
- None

## Out of scope
- Aggregations (per day, per referrer)
- Retention / purge policy
- IP or geo tracking
